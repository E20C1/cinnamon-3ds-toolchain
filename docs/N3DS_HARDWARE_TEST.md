# New 3DS hardware validation

The reproducible 3DSX build is now complete on Windows. The remaining Milestone 2 acceptance step is to run that exact build on New Nintendo 3DS hardware and confirm that UNDERTALE reaches playable behavior.

## Important: data.win is still required at runtime

The current 3DS runtime loads the GameMaker code/metadata from:

```text
romfs:/data.win
```

when present, otherwise it falls back to:

```text
sdmc:/3ds/cinnamon/data.win
```

The current Windows build embeds the **preprocessed graphics/audio asset tree** into RomFS, but it intentionally does not copy the original proprietary `data.win` into the 3DSX. Therefore this Milestone 2 hardware test needs the user's own `data.win` on the SD card.

This is separate from the later personal self-contained CIA workflow.

## Stage the SD-card files

After a successful `build-windows-n3ds.ps1` run:

```powershell
.\scripts\stage-n3ds-sd.ps1 -DataWin "C:\path\to\UNDERTALE"
```

The directory form is accepted; the script automatically selects `data.win` inside it.

This creates:

```text
build/sd-card/
└─ 3ds/
   └─ cinnamon/
      ├─ cinnamon.3dsx
      └─ data.win
```

and records hashes in:

```text
build/repro/n3ds-sd-stage.json
```

You can also copy directly to a mounted SD card in one command:

```powershell
.\scripts\stage-n3ds-sd.ps1 ^
    -DataWin "C:\path\to\UNDERTALE" ^
    -SdRoot "E:\"
```

In PowerShell, replace the caret line continuations above with a single line or PowerShell backticks. Replace `E:\` with the actual SD-card root.

## DSP firmware

The current audio backend calls libctru `ndspInit()`. libctru looks for the DSP component at:

```text
sdmc:/3ds/dspfirm.cdc
```

On Luma3DS **v11.0 or newer**, open Rosalina (default combo: **L + D-Pad Down + Select**), choose **Miscellaneous options**, then **Dump DSP firmware**. Luma writes `/3ds/dspfirm.cdc` to the SD card.

Older Luma builds such as **v9.1** do not contain this Rosalina menu item. If the option is absent, update Luma using the current Luma3DS / 3DS Hacks Guide update procedure before continuing, rather than treating the missing menu item as a Cinnamon problem.

This only needs to be done once per SD setup.

## Expected SD layout

```text
SD:/
└─ 3ds/
   ├─ dspfirm.cdc
   └─ cinnamon/
      ├─ cinnamon.3dsx
      └─ data.win
```

The graphics/audio generated by `n3ds-preprocess` are already inside the current 3DSX build's RomFS, so they do not need to be copied separately for this first test.

## Launch

Open the Homebrew Launcher and start `cinnamon`.

The expected startup sequence is approximately:

```text
Scanning data.win
Parsing chunk ...
Loading sound bank
Initializing renderer
<UNDERTALE starts>
```

The runtime creates `sdmc:/3ds/cinnamon` if needed and uses it as the writable save-data base.

## What to report from the first hardware run

Record whether the Homebrew Launcher lists and starts Cinnamon; the last visible loading message if startup stops; whether title/menu graphics render correctly; whether music and sound effects play; whether D-pad / Circle Pad / A / B / START input works; whether the first room can be entered and played; and any crash screen or Luma exception details.

A successful build alone does not complete Milestone 2. Hardware acceptance is reached once this exact 3DSX launches and reaches playable UNDERTALE behavior on the New Nintendo 3DS family.
